第 23 章 安装 Skill：把专业能力装进 WorkBuddy ​

这一章只解决一个问题：当 WorkBuddy 缺少某个专业能力（例如写公文、处理表格）时，怎样把现成的 Skill 装上并真正用起来。 读完你会掌握六种安装方式的选择路径，并能独立完成「选来源 → 安装 → 启用确认 → 重启 → 试用验收」的完整闭环，出问题时知道怎么回退。

本章演示以"公文写作"为主题：一个来自公开开源仓库的技能 wenshu，以及一个合成技能「会议纪要整理助手」。所有技能名、仓库地址与命令都以可复制文本框呈现；安装任何第三方技能前，先看它的 SKILL.md 和附带脚本内容。

先记住一条

装 Skill 前先确认来源：优先官方市场；第三方技能先读 SKILL.md 和附带脚本，确认没有可疑操作再装。装完不等于能用，必须完成「启用确认 + 重启 + 试用验收」三步。安装通常只往技能目录写文件，不修改你的业务数据，但涉及敏感目录的技能应先备份再试用。

30 秒看懂本章 ​

你遇到的问题用哪种方式最后得到什么
官方市场里就有想要的技能方式一 可视化安装已启用的技能
知道需求但不确定技能名方式二 对话搜索安装推荐并装好的技能
同事发来一个 ZIP 技能包方式三 本地上传 ZIP自动配置好的技能
熟悉命令行，想批量部署方式四 npx 命令安装装进技能目录的技能
GitHub 访问不稳定方式五 手动克隆或镜像手动放置的技能
想把自家流程固化成技能方式六 本地创建 Skill自建技能

完整流程只需六步：

开始前准备 ​

  1. 电脑上已安装并登录 WorkBuddy（见第 2 章）。
  2. 想清楚要什么能力：给谁用、解决什么问题、在什么场景触发。
  3. 确认网络：安装 GitHub 来源的技能需要能访问 GitHub；不能访问时，备好镜像地址或 ZIP 包。
  4. 知道技能目录位置：macOS/Linux 下为 ~/.workbuddy/skills/；Windows 请按本机用户目录对应查找。

文本框怎么用

下面深色文本框右上角有"复制"按钮。技能名、仓库地址与你的实际情况不同时，只改对应名称；安装完成后必须做「启用确认 + 重启 + 试用」，不能省略。

示例一：可视化界面安装（最省事） ​

合成场景：想给 WorkBuddy 加一个处理 Excel 的能力，官方市场里有现成技能。

1. 打开技能入口 ​

打开 WorkBuddy，左侧导航栏找到「技能 · 专家 · 连接器」入口，进入「技能」Tab，这里列有官方推荐技能。

2. 搜索并安装 ​

在技能列表中找到目标技能，点加号一键安装。安装后在「已安装」Tab 确认状态为已启用。

3. 验收 ​

  • 技能面板「已安装」里能看到该技能且状态为启用。
  • 重启 WorkBuddy 后，在对话中描述对应任务，能触发该技能。

复制验收提示词

text
请确认「Excel 处理」技能已安装并启用。我接下来会给一个表格文件，按技能说明完成清洗和汇总。

示例二：对话中搜索安装（不用翻界面） ​

适合：不知道技能确切名字，只知道自己想干什么。

复制提示词 1：搜索并安装

text
帮我找一个能写公文的技能，找到合适的就直接安装。

WorkBuddy 会自动加载技能搜索能力，搜索技能生态并推荐匹配项，看到合适的让它直接装。

也可以直接给仓库地址：

复制提示词 2：指定仓库安装

text
帮我安装这个技能：https://github.com/aether-liusiqi/wenshu

WorkBuddy 会处理后续的克隆、配置、启用流程。

验收 ​

  • 对话中看到安装成功的确认。
  • 技能目录（~/.workbuddy/skills/）中出现对应技能文件夹。

示例三：本地上传 ZIP 导入 ​

适合：同事发来技能 ZIP 包，或从 GitHub 下载了 ZIP（GitHub 访问不稳定时的常用备选）。

  1. 在 WorkBuddy 里点「添加技能」→「上传技能」。
  2. 拖入 ZIP 文件，或点击选择文件。
  3. 系统自动解压并放到正确位置，无需手动处理目录结构。

验收 ​

  • 技能面板出现该技能。
  • 重启后试用一次对应任务，确认能触发。

示例四：命令行安装（极客路线） ​

适合：技术人员批量部署、GitHub 上按标准格式发布的开源技能。

bash
# 搜索技能
npx skills find "wenshu"

# 安装（-g 全局安装，-y 跳过确认）
npx skills add aether-liusiqi/wenshu@wenshu -g -y

# 确认结果
ls ~/.workbuddy/skills/

注意：据来源文章，该命令由 Skills CLI 工具提供，会检索技能仓库后克隆到 ~/.workbuddy/skills/ 目录；owner/repo@skill 的写法区分大小写，写错会报错。

验收 ​

  • ls ~/.workbuddy/skills/ 能看到 wenshu 目录。

示例五：GitHub 手动克隆（最稳） ​

适合：命令行命令报错、GitHub 访问不稳定但有镜像，或想完全自己控制。

bash
git clone https://github.com/aether-liusiqi/wenshu.git ~/.workbuddy/skills/wenshu/

克隆完成后，据来源文章的经验，还需要在 ~/.workbuddy/settings.json 确认启用配置，格式类似：

json
{
  "enabledPlugins": {
    "wenshu@codebuddy-plugins-official": true
  }
}

保存后完全退出并重启 WorkBuddy，让配置生效。

验收 ​

  • 技能目录结构完整（SKILL.md、references/、scripts/ 等）。
  • 重启后对话中能触发该技能。

示例六：本地创建自定义 Skill ​

适合：把自家总结的流程固化成技能，不对外公开。

复制提示词：让 WorkBuddy 生成

text
帮我把刚才跑的那个流程做成一个 Skill，取名叫 xxx

或从零创建：

text
帮我创建一个技能，名字叫公文写作助手

SKILL.md 的标准结构是 YAML 前言加 Markdown 正文：

markdown
---
name: wenshu
description: 专业中文公文写作助手。覆盖15种法定文种+7种事务文书
author: 你的名字
version: 1.0.0
tags:
  - writing
  - government
  - documents
---

写完放入 ~/.workbuddy/skills/你的技能名/，重启 WorkBuddy 生效。

验收 ​

  • 重启后技能被识别、可触发。
  • description 描述准确，便于在合适场景自动加载。

装完后：试用、读边界、控数量 ​

  1. 先读 SKILL.md：确认它擅长什么、不擅长什么。以 wenshu 为例，它擅长通知、报告、请示、函、纪要等正式公文，不是文学创作和广告文案。
  2. 试用一次：触发对应任务，检查输出格式是否符合预期。
  3. 控制数量：据来源文章建议，普通用户装 5–10 个、专业用户 10–15 个、不超过 20 个；只装当下用得上的，不用的在「技能」面板关闭即可，无需卸载。

常见弯路 ​

  • GitHub 连不上：内网或访问不稳定时，命令安装或克隆会卡死。备选：上代理、用镜像站（如把 github.com 换成镜像域名）、在 GitHub 点 Download ZIP 后走方式三导入、跳过下载直接本地创建。
  • 装完对话不认：目录在但对话不触发，通常是未启用。检查 settings.json 的 enabledPlugins 是否有该技能，保存后重启。
  • 多平台混装缺依赖：部分技能带 Python 脚本，需要额外装依赖（如 pip install python-docx）；Windows 上注意脚本里的路径分隔符（Linux/macOS 用 /，Windows 用 \）。
  • 装太多拖速度：技能越多，每次加载时的上下文越大。控制在 20 个以内，不用的及时关闭。
  • 不核实来源就装：第三方技能装之前先看 SKILL.md 和脚本内容，确认没有可疑操作再装。

替换参数 ​

换成你自己的场景时，需要替换：

参数示例值换成什么
技能名wenshu你要安装的技能名
仓库地址github.com/aether-liusiqi/wenshu实际来源地址
技能目录~/.workbuddy/skills/本机技能目录
启用配置名wenshu@codebuddy-plugins-official实际插件名
试用任务写一份组织年度工作会议的通知你的实际任务

人工确认点与安全边界 ​

  • 安装第三方技能前，先读 SKILL.md 与附带脚本，确认来源可信、行为可预期。
  • 涉及文件写入、网络外发、账号凭据的技能，先小范围试用，确认行为符合预期再正式使用。
  • 官方市场优先；开源技能以仓库页面描述为准。本文命令、路径与数量建议来自来源文章，具体以你所用版本的官方文档为准，不确定的项标记「待确认」。
  • 安装不自动修改业务数据；不确定的操作先备份工作目录。
  • Skill 只提供方法和步骤，不替代正式制度、权限和专业审核。
