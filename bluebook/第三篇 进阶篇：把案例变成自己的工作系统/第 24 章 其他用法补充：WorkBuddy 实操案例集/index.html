第 24 章 备份、校验与恢复演练 ​

备份的价值由恢复结果决定。看到“复制完成”或“同步成功”只能说明流程执行过；只有校验通过，并且资产已经在新的空目录中恢复且能够继续使用，才能证明恢复链路有效。

本章提供通用治理方法，不指定公司正式存储系统、保留周期或恢复责任。具体位置、权限、保密要求和恢复目标应由信息化、安全、业务和资料责任人共同确认。

需要保护哪些 AI 协作资产 ​

资产类别建议纳入范围恢复后检查什么
成果资产正式文件、项目数据、代码、图片及验收记录文件可打开，数量、版本和关键内容一致
协作资产任务规则、模板、Skill、已确认记忆和维护说明Agent 能读取正确版本，规则和来源关系完整
连续性资产快照、文件清单、校验结果、恢复说明和演练记录能找到可用时间点，恢复步骤和责任人清楚

密钥、Token、密码、私钥、个人账号文件、缓存和原始会话记录默认排除。确需备份的敏感配置应使用公司批准的凭证管理和加密方案，不得混入普通协作资产包。

备份、同步和恢复分别解决什么 ​

能力主要作用需要注意的限制
工作目录保存当前正在使用的最新状态误删、误改会立即影响正式资产
同步在设备或服务之间保持接近一致的状态删除和错误也可能被同步传播
时间点快照保留多个独立历史状态同盘快照无法应对整块磁盘损坏
异地副本应对设备、磁盘或单一位置不可用必须使用公司批准的位置和访问权限
恢复演练证明快照完整、步骤可执行、工作能够接续应恢复到新位置并记录验收结果

一个可靠方案通常同时保留当前工作目录、多个独立时间点和经过批准的第二位置，并定期做恢复演练。

六步闭环 ​

1. 建立资产与责任清单 ​

列出需要保护的目录、文件类型、负责人、敏感级别、更新频率、允许存放的位置和恢复优先级。没有明确来源或无权保存的材料不得擅自纳入。

2. 生成独立时间点快照 ​

快照放在工作目录之外，使用日期和批次形成独立目录。生成时记录成功、跳过、排除和失败项；重复运行不能静默覆盖已有快照。

3. 生成并检查校验清单 ​

为快照生成文件路径、数量、大小和哈希等校验信息。校验要能发现缺失、损坏和意外新增的敏感文件。看到脚本退出成功仍需检查清单和日志。

4. 管理保留周期和第二位置 ​

根据资产变化频率和恢复目标保留多个时间点。需要应对磁盘、设备或办公地点故障时，将快照复制到公司批准的第二介质或异地存储；不得自行上传到个人云盘或未批准服务。

5. 恢复到新的空目录 ​

选择一个已校验快照，恢复到不包含现有文件的目标目录。演练阶段不覆盖正式工作区，也不直接写回 Agent 的用户级配置。

6. 验收并留下演练记录 ​

至少完成以下检查：

  • 资产目录和必需文件完整，文件数量与校验清单一致。
  • 抽样文件可以打开，关键数据、版本和引用关系正确。
  • 至少一个模板或 Skill 能被读取并完成脱敏测试任务。
  • 已确认记忆、来源、状态和适用范围能够继续查询。
  • Agent 可以根据恢复后的规则接续一个测试任务。
  • 演练日期、快照时间、执行人、验收人、问题和修正措施已经记录。

恢复演练流程 ​

合成示例：一份项目资料的恢复演练 ​

某测试项目包含 20 份文档、1 份任务规则和 1 份校验清单。执行人先确认快照中不含凭证和个人信息，再将它恢复到一个新建的空目录。验收人核对文件数量和校验值，抽样打开文档，并使用恢复后的任务规则完成一次脱敏测试。只有数量、校验值、抽样文件和测试任务全部通过，该快照才被记录为可用恢复点。

可复制恢复演练模板 ​

text
请对这份 AI 协作资产快照执行只读校验和恢复演练。

快照位置：{位置}
恢复目标：{必须为空的新目录}
资产责任人：{责任人}
本次验收人：{验收人}
允许读取范围：{范围}
禁止写入范围：{正式目录、用户级配置、外部系统等}

请按以下步骤执行：
1. 检查快照目录、文件数量、校验清单和日志；
2. 发现缺失、损坏、敏感文件或路径异常时立即停止；
3. 校验通过后恢复到指定空目录，不覆盖现有目录；
4. 检查必需文件，并抽样打开成果文件；
5. 检查一个模板或 Skill、已确认记忆及其来源关系；
6. 使用恢复目录完成一个脱敏测试任务；
7. 输出演练结果、问题清单、可用恢复点和修正建议。

没有责任人确认，不替换正式目录，不恢复账号凭证，不重新开启自动化。

发生事故后的恢复顺序 ​

  1. 停止仍在运行的 Agent、脚本、同步和自动重试。
  2. 保护现场日志、受影响目录和时间信息，避免继续写入。
  3. 确认最近一个未受影响且校验通过的快照。
  4. 在新的空目录恢复并完成验收。
  5. 由责任人确认业务影响、丢失范围和正式恢复方案。
  6. 替换正式资产前再次建立当前现场副本，保留调查和回退能力。
  7. 恢复完成后收回临时权限，修正触发条件、备份范围或处置流程。

常见弯路与安全边界 ​

  • 只检查备份任务显示“成功”，无法发现文件缺失、排除规则错误和快照损坏。
  • 把同步目录当作唯一恢复来源，误删和误改可能已经传播到所有设备。
  • 只保留最新一份副本，发现问题较晚时无法回到更早的可信状态。
  • 在正式目录上直接测试恢复，会覆盖现场并扩大影响。恢复演练必须使用空目录。
  • 未检查敏感文件排除结果，可能把凭证和个人信息复制到更广范围。
  • 备份位置、访问权限、保留期限和销毁方式必须符合公司制度和第三方材料授权。

验收标准 ​

  • 快照包含经过确认的资产范围，并有清单、校验值和运行日志。
  • 至少保留多个可识别时间点，第二位置符合公司批准范围。
  • 恢复操作在空目录完成，没有覆盖正式资产和用户级配置。
  • 文件、Skill、记忆和测试任务均通过验收。
  • 演练记录能够说明使用了哪个快照、发现了什么问题、由谁确认和怎样修正。

实操案例：把销售数据生成可交互 HTML 可视化看板 ​

本节只解决一个问题：已经把数据整理干净、口径确认之后，怎样让 WorkBuddy 生成一个可交互 HTML 看板和对比分析报告，并保留“先检查—再确认—后执行—再核对”的控制链。

适用情境：月度或季度销售汇报需要同时交付数据明细、趋势图、对比分析和可落地建议。读者按本节做完后，会得到一个 HTML 看板文件、一份对比分析报告和一条可追溯的核对说明。

先记住一条

  • 不要把原数据表交给 AI 直接覆盖；先复制一份到独立工作目录。
  • 个人信息、客户名单、未公开经营数据不得外传；进入 HTML 看板前先做脱敏。
  • 产品入口随版本变化，下列“日常办公 → 数据分析及可视化”“专家板块 → 数据分析师”仅为路径示例，以当前客户端为准。

30 秒看懂本节 ​

你的目标复制哪段提示词得到什么
先看数据是否可用提示词 1：数据体检字段、行数、异常清单和拟展示维度
生成可交互看板提示词 2：HTML 看板生成HTML 看板 + 元信息表 + 异常保留说明
同时做对比分析提示词 3：对比分析扩展环比、Top5/Bottom5、改进建议与限制说明

第一次跟做只要六步：

开始前准备 ​

  1. 新建一个文件夹，例如 第24章-可视化看板练习。
  2. 准备一份合成的销售样例表 synthetic-monthly-sales.csv，至少包含：日期、区域、产品、销售额、订单数。本节示例数据全部为合成数据，请勿直接套用真实经营数据。
  3. 在 WorkBuddy 中选择该目录作为工作空间；可用入口如“日常办公 → 数据分析及可视化”或“专家板块 → 数据分析师”，以当前客户端为准。

合成样例示意（仅供参考字段结构，不作为业务事实）：

日期区域产品销售额订单数
2026-07-01华北产品 A128012
2026-07-02华东产品 B9809
2026-07-03华南产品 A156015
2026-07-04华中产品 C7607
2026-07-05华北产品 B-320-3

第五行故意放入负数（退货冲正），用于验证异常不会被偷偷删除或隐藏。

步骤一：数据体检，不直接画图 ​

复制提示词 1：数据体检

text
请只读检查工作目录中的 synthetic-monthly-sales.csv，先不要生成任何图表或看板。

请报告：
1. 字段名、记录数、空值和重复行；
2. 数值列的最小值、最大值、合计与负值出现位置；
3. 日期范围与是否存在跨期记录；
4. 分类字段的取值与各自样本量；
5. 可用于展示的维度与指标组合；
6. 拟生成的看板草图与可能涉及的口径问题。

已知条件：本表为 2026 年 7 月的合成销售数据。
等我确认维度、口径和异常处理后，再生成看板。

人工确认点

  • 区域、产品、时间维度是否就是这次汇报要展示的维度。
  • 负数是否为退货冲正，是否要在看板中单独标注。
  • 时间按日、按周还是按月聚合。
  • 单位是否需要从“元”换算为“万元”。

步骤二：生成可交互 HTML 看板 ​

只有当数据体检报告中的字段、行数、异常位置和拟展示维度都核对无误后，才复制下一段提示词。

复制提示词 2：HTML 看板生成

text
基于已确认的体检结果生成一份可交互 HTML 看板，保存为 sales-dashboard.html。

要求：
1. 看板包含：销售趋势折线图、区域占比饼图、产品销售额 Top5 柱状图；
2. 支持按区域、产品筛选，筛选切换时所有图表同步更新；
3. 每张图写明：标题、单位、时间范围、样本量和数据更新时间；
4. 负数（退货冲正）不得隐藏；在趋势图和 Top5 中单独显示，并在图例标注“退货冲正”；
5. 不展示未在数据中出现的分类；缺失值显示为“无数据”，不补零；
6. 同步生成 dashboard-meta.md：列出数据来源文件、行数、字段、图表清单、异常处理说明和原文件路径。

不要修改原 csv 文件。生成完成后请报告：生成的文件名、图表数量、异常保留情况和总销售额。

图 24-1　合成示例：演示循环展示"输入提示词 → 数据体检 → 生成看板 → 筛选交互"四阶段；负值（退货冲正 -320 元）在趋势图、占比图、柱状图中均单独标注，不得隐藏。原始数据 5 行均为合成，不构成对原文事实的延伸。

验收只看四点

  1. 浏览器打开 HTML 后，筛选可正常切换并同步刷新所有图表；
  2. 每张图都标注了标题、单位、时间范围、样本量和更新时间；
  3. 负数或退货冲正没有被“漂亮化”掉；
  4. 原 csv 文件未被修改，dashboard-meta.md 能追溯到来源。

步骤三：扩展到对比分析 ​

如果汇报同时需要环比、Top5/Bottom5 和改进建议，在前一步结果通过验收后再使用下一段提示词。它要求每条结论绑定具体指标，并明确区分“基于数据的结论”与“建议”。

复制提示词 3：对比分析扩展

text
基于已确认无误的销售数据生成对比分析报告 comparison-report.md。

请完成：
1. 计算环比增长率，并标出负增长的记录；
2. 计算各区域、各产品的销售额占比；同比需注明是否使用了同期对照数据，未提供同期数据时只做环比并明确说明；
3. 输出 Top5 和 Bottom5 排名表；
4. 给出 3 条可落地改进建议，每条建议引用至少一个具体指标作为依据；
5. 明确标注哪些是“基于数据的结论”，哪些是“建议”；建议不得暗示已被经营层采纳；
6. 列出缺失值、小样本、未匹配和待确认事项，不得用相关性推断因果。

同步输出 comparison-meta.md：列出输入文件、行数、计算口径、异常处理和差异说明。
不要覆盖原文件，不要外发，不要发布到外部平台。

步骤四：修正闭环 ​

如果生成的看板或报告出现下列任一情况，不要手工改完就结束，要让 WorkBuddy 按修正后的规则重新生成：

  • 模型擅自删除了负值或异常行；
  • 图表缺少单位、时间范围或样本量；
  • 结论没有引用具体指标；
  • 同比/环比计算口径未声明。

复制提示词 4：发现错误后修正

text
请不要直接改一处就结束。

先说明本次输出存在哪些问题；
把修正规则补充到规则清单；
再重新生成 sales-dashboard-v2.html 和 comparison-report-v2.md；
最后重新报告：图表数量、异常保留情况、总销售额、Top5/Bottom5 与上一版的差异。

换成自己的文件时，只改这几处 ​

占位内容改成什么
synthetic-monthly-sales.csv你的实际文件名
日期、区域、产品、销售额你的字段名
按区域/产品/日聚合你确认的聚合粒度
单位“元”或“万元”你确认的口径
Top5/Bottom5你确认的排名范围
输出文件名你希望交付的文件名

不要删除这些句子：

  • 先检查，等我确认后再执行。
  • 不要覆盖原文件。
  • 无法判断的内容标记“待确认”。
  • 输出处理前后的行数、关键金额和差异核对。

常见弯路 ​

  • 跳过数据体检直接生成看板，导致负值被自动忽略或字段含义被猜测。
  • 图表只看美观不核对元信息，单位、时间范围或样本量缺失。
  • 同比未声明是否使用同期对照数据，导致读者误以为是同期可比。
  • 把“销售额和广告投入相关”直接写成“广告投入提升了销售额”。
  • 把改进建议写成已被公司采纳的结论。

人工确认点 ​

  • 输入材料是否合法、完整、允许用于本次处理，是否包含个人信息或未公开经营数据。
  • 展示维度、聚合粒度、单位、口径是否符合汇报要求。
  • 负数、退货、跨期、未匹配等异常如何呈现。
  • 看板是否需要外发；如需外发，使用公司批准的渠道并脱敏。
  • 改进建议是否仅作为参考，而非作为经营事实或财务结论。

安全边界 ​

  • 不向未批准的外部服务上传敏感表格、个人信息和未公开经营数据。
  • 不把模型推断当作业务事实、财务结论或管理决定。
  • 不自动覆盖源文件、不自动外发、不自动发布或提交审批。
  • 对小样本、自由文本和联系方式做脱敏或限制访问。
  • 产品入口、界面和能力可能随版本变化，以当前客户端和官方说明为准。
